## 1. ข้อกำหนดระบบพร้อมต์ของแบบจำลองเอไอ (System Prompt Specification)

การประยุกต์ใช้งานเทคโนโลยี Generative AI ในโปรแกรมระบบให้คำปรึกษาการควบคุมน้ำหนักนี้ ได้เลือกใช้โมเดล Google Gemini 2.0 Flash (`gemini-3.6-flash`) เป็นหลัก โดยกำหนดโครงสร้างของคำสั่งระบบ (System Instruction) เพื่อควบคุมบทบาท ความแม่นยำทางโภชนาการ และความปลอดภัยทางการแพทย์อย่างเข้มงวด ดังมีรายละเอียดโครงสร้างคำสั่งระบบต่อไปนี้

### 1.1 โครงสร้างคำสั่งระบบต้นแบบ (System Instruction Template)
```text
บทบาทหน้าที่:
คุณคือ "Happy Health Chatbot" นักกำหนดอาหารประยุกต์และผู้เชี่ยวชาญด้านวิทยาศาสตร์การกีฬา มีหน้าที่ให้ข้อมูลและคำแนะนำเกี่ยวกับการควบคุมน้ำหนัก โภชนาการ และการออกกำลังกายที่ถูกต้องตามหลักวิทยาศาสตร์

ข้อมูลส่วนบุคคลของผู้ใช้ปัจจุบัน (User Context Injection):
- เพศ: {gender}
- อายุ: {age} ปี
- น้ำหนักปัจจุบัน: {weight} กิโลกรัม
- ส่วนสูง: {height} เซนติเมตร
- อัตราการเผาผลาญพื้นฐาน (BMR): {bmr} กิโลแคลอรีต่อวัน
- พลังงานที่ใช้ในกิจกรรมประจำวัน (TDEE): {tdee} กิโลแคลอรีต่อวัน

ข้อบังคับในการตอบคำถาม:
1. การแนะนำพลังงานอาหาร: แนะนำอาหารให้สอดคล้องกับค่า TDEE เพื่อสร้าง Caloric Deficit (ประมาณ 300 ถึง 500 กิโลแคลอรีต่อวันสำหรับผู้ต้องการลดน้ำหนัก)
2. รูปแบบและความยาวการแสดงผล: ตอบกลับผู้ใช้งานไม่เกิน 1 ย่อหน้า และไม่เกิน 300 ตัวอักษร เพื่อให้อ่านง่ายบนหน้าจอมือถือของแอปพลิเคชัน LINE
3. มาตรฐานความปลอดภัยทางการแพทย์: หากมีการถามเรื่องโรคประจำตัว อาการป่วยเฉียบพลัน หรือการใช้ยาลดน้ำหนัก ให้ตอบปฏิเสธอย่างสุภาพและแนะนำให้เข้าพบแพทย์ผู้เชี่ยวชาญทันที
4. โทนเสียงการสนทนา: ใช้น้ำเสียงที่เป็นมิตร สุภาพ สร้างแรงบันดาลใจ และใช้คำทับศัพท์ทางการแพทย์เท่าที่จำเป็นเท่านั้น
```

## 2. ท่อประมวลผลการคำนวณและป้อนข้อมูลสุขภาพส่วนบุคคล (Context Injection Protocol)

ก่อนการส่งข้อความของผู้ใช้ไปยังโมเดล Google Gemini ระบบของ Laravel 12 จะทำการคำนวณข้อมูลสุขภาพเบื้องต้นแบบอัตโนมัติ เพื่อประกอบเป็นข้อมูลบริบท (Context) ป้อนลงในคำสั่งระบบอย่างจำเพาะเจาะจง

### 2.1 สูตรการคำนวณทางโภชนาการเชิงระบบ
1. **สูตร Mifflin-St Jeor สำหรับคำนวณ BMR**:
   * เพศชาย: BMR = (10 x น้ำหนักตัวเป็นกิโลกรัม) + (6.25 x ส่วนสูงเป็นเซนติเมตร) - (5 x อายุเป็นปี) + 5
   * เพศหญิง: BMR = (10 x น้ำหนักตัวเป็นกิโลกรัม) + (6.25 x ส่วนสูงเป็นเซนติเมตร) - (5 x อายุเป็นปี) - 161
2. **การหาค่า TDEE ตามระดับกิจกรรมประจำวัน**:
   * นั่งทำงานอยู่กับที่หรือออกกำลังกายน้อยมาก: TDEE = BMR x 1.2
   * ออกกำลังกายเบาๆ 1 ถึง 3 วันต่อสัปดาห์: TDEE = BMR x 1.375
   * ออกกำลังกายปานกลาง 3 ถึง 5 วันต่อสัปดาห์: TDEE = BMR x 1.55
   * ออกกำลังกายหนัก 6 ถึง 7 วันต่อสัปดาห์: TDEE = BMR x 1.725

### 2.2 โฟลว์การประกอบบริบท (Prompt Compilation Workflow)
1. **การดึงข้อมูล**: แพลตฟอร์มรับรหัสผู้ใช้ผ่านระบบ Webhook ของ LINE แล้วดึงข้อมูลโปรไฟล์และการตั้งค่าเป้าหมายจากฐานข้อมูล SQLite / MySQL
2. **การประมวลผลข้อมูลหลังบ้าน**: นำข้อมูลสัดส่วนสรีระมาคำนวณ BMR และ TDEE ผ่านชุดคำสั่ง PHP
3. **การส่งต่อคำสั่ง**: นำค่าโภชนาการที่คำนวณได้ป้อนเข้าไปแทนที่ค่าตัวแปร (Variables) ในโครงสร้าง System Prompt จากนั้นแนบข้อความล่าสุดของผู้ใช้และส่งคำร้องขอ (API Request) ไปยังเซิร์ฟเวอร์ของ Google Gemini

## 3. คลังข้อมูลอ้างอิงและเกราะป้องกันทางการแพทย์ (Knowledge Base and Medical Guardrails)

เพื่อความมั่นคงและปลอดภัยของระบบคำแนะนำ ได้มีการกำหนดเกณฑ์การประเมินและการกรองเนื้อหา (Content Filtering Guidelines) ร่วมกับแพทย์และนักกำหนดอาหารวิชาชีพ

### 3.1 ตารางแนวทางการตอบกลับและเกราะคัดกรองคำถามที่เป็นอันตราย (Guardrail Rules Table)

| ประเภทหัวข้อคำถาม | ข้อมูลอ้างอิงที่แนะนำให้ใช้ (Approved Guide) | รูปแบบคำตอบที่ผ่านความเห็นชอบ | การคัดกรองสกัดกั้นของระบบ (System Mitigation) |
| :--- | :--- | :--- | :--- |
| คำนวณพลังงานมื้ออาหาร | ฐานข้อมูลสารอาหารท้องถิ่นไทย และอัตราส่วนพลังงาน 40:30:30 | แนะนำอาหารไทยพร้อมคำนวณกิโลแคลอรีโดยเทียบกับเป้าหมาย TDEE | ระบบอนุญาตให้ประมวลผลตามปกติ |
| การออกกำลังกายเบื้องต้น | โปรแกรมแอโรบิก แรงต้าน และคาร์ดิโอขั้นพื้นฐานของสมาคมกีฬา | แนะนำประเภทการออกกำลังกายและระยะเวลาที่เหมาะสม (เช่น 150 นาทีต่อสัปดาห์) | ระบบอนุญาตให้ประมวลผลตามปกติ |
| การใช้ยาลดน้ำหนัก | ห้ามอ้างอิงข้อมูลยาลดความอ้วนหรือสารสกัดควบคุมน้ำหนักทุกชนิด | "ระบบไม่สามารถให้ข้อมูลการใช้ยาลดน้ำหนักได้ แนะนำให้ปรึกษาแพทย์เฉพาะทางเพื่อความปลอดภัยค่ะ" | ระบบตอบกลับด้วยข้อความปฏิเสธแบบตายตัว (Static Bypass Message) |
| ผู้ใช้งานแจ้งข้อมูลเป็นโรคหัวใจ/ไต | การจำกัดโซเดียมและของเหลวตามมาตรฐานสมาคมแพทย์โรคไต | "ข้อมูลสุขภาพของท่านมีข้อควรระวังเรื่องโรคประจำตัว โปรดขอคำแนะนำจากแพทย์ประจำตัวเพื่อป้องกันอันตรายค่ะ" | ระบบจำกัดเนื้อหาและห้ามแนะนำเมนูอาหารที่มีความเสี่ยงสูงแบบอัตโนมัติ |
| ลิงก์แปลกปลอมและโค้ดอันตราย | กรองข้อมูลนำเข้าที่เป็น URL หรือ HTML Script ทุกรูปแบบ | ส่งกลับข้อความเตือนความปลอดภัย และไม่อนุญาตให้ผ่านเข้าถึงโมเดล AI | บล็อกการทำงานทันทีผ่านตัวกรอง regex และ `isUrl` Function ฝั่ง Backend |

## 4. รายงานผลการประเมินความถูกต้องและความรวดเร็ว (AI Accuracy & Latency Report)

การประเมินประสิทธิภาพของระบบปัญญาประดิษฐ์ ดำเนินการโดยเปรียบเทียบการตอบของโมเดล AI กับชุดตัวเลือกมาตรฐาน (Ground Truth Questions) ที่จัดทำโดยผู้เชี่ยวชาญจำนวน 50 ข้อคำถามหลัก

### 4.1 ตารางผลสัมฤทธิ์การประเมินการตอบสนองของระบบ (Performance Metric Table)

| ดัชนีชี้วัดหลัก (Key Performance Indicator) | ค่าเป้าหมายขั้นต่ำที่กำหนด | ผลลัพธ์จากการทดลองใช้จริง | สถานะการประเมิน |
| :--- | :---: | :---: | :---: |
| ความแม่นยำด้านข้อมูลโภชนาการ (Nutrition Accuracy) | ร้อยละ 85.00 | ร้อยละ 92.00 | ผ่านเกณฑ์ |
| ความปลอดภัยจากภัยคุกคามสแปมลิงก์ (URL Mitigation) | ร้อยละ 100.00 | ร้อยละ 100.00 | ผ่านเกณฑ์ |
| อัตราความรวดเร็วในการตอบกลับเฉลี่ย (Response Latency) | น้อยกว่า 3.0 วินาที | 2.4 วินาที | ผ่านเกณฑ์ |
| การควบคุมรูปแบบขนาดความยาว (Length Constraint Compliance) | ร้อยละ 90.00 | ร้อยละ 94.00 | ผ่านเกณฑ์ |

### 4.2 สรุปผลสัมฤทธิ์
1. ความเร็วการตอบกลับเฉลี่ย (Latency) วัดผลจากการจำลองเรียกใช้งาน API ผ่านระบบเครือข่ายอินเทอร์เน็ต พบว่าระบบประมวลผลเบื้องหลังและการดึงบริบทช่วยลดขั้นตอนลง ส่งผลให้เวลาตอบสนองอยู่ในระดับดีเยี่ยม (2.4 วินาที) ช่วยลดปัญหาการเชื่อมต่อขาดตอน (Timeout) ใน LINE Messaging API
2. การวิศวกรรมพร้อมต์ผ่าน System Instruction ช่วยสกัดการแสดงผลที่ไม่พึงประสงค์ได้เป็นอย่างดี ป้องกันการให้คำแนะนำทางโภชนาการที่ผิดพลาดได้อย่างมีประสิทธิภาพ ช่วยสร้างระบบนิเวศน์ทางสุขภาพที่ปลอดภัยแก่ผู้ควบคุมน้ำหนักในโครงการทดลอง
